# OrGigs

**It's an organ.** Three manuals with 84 free-running tone generators and no voice stealing, eight models from
tonewheel and combo organs to pipe organs and free reeds, drawbars, percussion, rotary, drive, delay and reverb,
16 performance setups, three MIDI zones and Yamaha SEQTRAK control. Firmware for the **M-VAVE SMK-37 Elite** and the
**M-VAVE FM-1**, built on [Dinghy](https://github.com/zvenson/dinghy) (Felucca / SLOOP's platform). Free and open
source, GPL-3.0.

if a keyboard doesn't start, hold **OCT−** while switching it on (USB rescue mode).

## For developers

```
firmware/src/orgigs.c             the app: picks the board, includes core and board (one compilation unit, as Dinghy builds)
firmware/src/                     Dinghy's platform: boot, USB, screen, flash, updater
firmware/core/                    the same on every board:
  orgigs_dsp.c/.h                 84 free-running generators, 8 models, 3 manuals          (audio interrupt)
  orgigs_fx.c                     per manual: drive/cassotto, vibrato/tremulant, sends; shared: rotary, delay, reverb (audio interrupt)
  orgigs_midi_zones.c             3 MIDI zones: router, cloner, 9-ch harmonic, chord memory (main loop)
  orgigs_presets.c                the drawbar list, 16 performance setups, the settings in flash (main loop)
  orgigs_ctl.c                    what a panel can do: drawbars, effects, rotary, setups, message line, saving (main loop)
firmware/board/fm1/               the M-VAVE FM-1:
  board.h                         its facts (27 keys from F3)
  orgigs_ui.c                     its panel, lights and screens: drawbars, FX, mixer, 4 MIDI screens, 240x240 (main loop)
  orgigs_intro.c, orgigs_selftest.c   the welcome screen; the emulator's self-playing test
firmware/gen/orgigs_tables.h      generated by tools/gen_orgigs_tables.py (wavetables, pitch, filters, reverb)
sim/                              the WebAssembly browser simulator
tests/                            the same firmware on a PC: script in, WAV + screens + MIDI log out
```

## Try it in the browser (no FM-1 needed)

```sh
sim/build_wasm.sh        # -> sim/web/orgigs_sim.js (needs the emsdk; already built)
sim/serve.sh             # -> http://localhost:8099  (Web MIDI needs http://localhost, not file://)
```

Open it in Chrome or Edge, click **Start audio**, play with the mouse or the PC keyboard (`Z`…`/` and
`Q`…`U`, piano layout), turn knobs with the wheel or by dragging. **Enable Web MIDI** to play it from a
keyboard (ch 1 upper, ch 2 lower, ch 3 pedal; CC 12–20 drawbars) and to send the zones' output to a synth or DAW.
The log on the page shows every outgoing message.

## Build the firmware

```sh
tools/get_toolchain.sh                                            # once: JieLi clang -> ~/.jieli/toolchain
git clone --depth 1 --branch AC79NN_SDK_V1.2.1_2023-12-13 \
    https://gitee.com/Jieli-Tech/fw-AC79_AIoT_SDK.git ~/fw-AC79_AIoT_SDK   # once
./build.sh                                                        # -> build/orgigs_fm1.fwsc
python3 tools/fm1_install.py build/orgigs_fm1.fwsc                # over USB; asks before it writes
python3 tools/orgigs_backup.py --save my.syx                      # the settings as a SysEx backup (--load: back)
```

**FM-1 emulator** (`fm1-emulator-linux-amd64`): `./emulator build/orgigs_fm1.fwsc`. It does not decode every
pi32v2 instruction, so the build also refuses the forms it is known to reject (a load with register
post-increment, a signed byte load from the stack). `./build.sh --selftest` makes `build/orgigs_fm1-selftest.fwsc`,
which plays itself (all models, manuals, screens, MIDI zone settings, presets, setups, settings save and reload), so the
emulator runs every code path: `./emulator --headless build/orgigs_fm1-selftest.fwsc` must still be running after
a few minutes. `./build.sh --tonetest` plays an A4 sine on/off (with `ORGIGS_CFLAGS="-DORGIGS_TONE_FULL"`: chords
with rotary, chorus and reverb) for recording the emulator's sound; add `-DORGIGS_PROF` and run the emulator with
`--qemu -machine fm1-poc -kernel build/orgigs_fm1.bin -icount shift=0 -monitor stdio` to read the instructions each
audio block costs (`xp /4wd <org_prof>`). Never install the self-test or tone-test builds on a device.

The emulator plays through SDL and PulseAudio; under WSL that goes over WSLg, which crackles with small buffers
whatever plays. If it does, try `PULSE_LATENCY_MSEC=60 ./emulator build/orgigs_fm1.fwsc`.

The build refuses what would brick the FM-1 (64-bit division, chip ROM calls, RAM over budget, register access
outside `hal/`). Installing firmware is at your own risk; the way back: hold **OCT-** at power-on (USB rescue),
or [The Firmware Hub](https://thefirmwarehub.com). The package identity is `FM-1_970`: check the hub
that nobody else uses it before you publish a release.

## Playing it

Panel buttons (as on the FM-1):  `FX SEL ENV LFO EDIT GLO` / `HOME SAVE ARP SEQ PLAY REC`. Everywhere: SELECT = manual (zone),
ALGORITHM = model, PRESETS = the drawbar list.

| Control | Function |
| --- | --- |
| KNOB 1–4 | the screen's four parameters; **hold SEL** for the second row (the FM-1's knobs have no push) |
| ENV / LFO / EDIT | drawbars 1–4 / 5–8 / 1, 3, 4 + 9 (in the MIDI zones: the screen's switches) |
| FX | the FX screen, a row per manual (ENV/LFO/ARP = UM/LM/PM): drive / vibrato·tremulant / delay send / reverb send, SEQ = the manual through the rotary; SEL: percussion·chiff·detune / delay feedback / delay time / reverb space. Again: back |
| GLO | the MIDI zones: ZONE → CLONE → HARMONIC → CHORD (HOME leaves) |
| HOME (on the drawbars) | the MIDI mixer: 16 channel volumes (CC 7) in 4 rows, ENV LFO / ARP SEQ = the row; HOME again: back |
| SEL + GLO | the panel lights: keys / buttons OFF · DIM (all glow) · FULL (all lit, what matters blinks), the dim level |
| SELECT encoder | manual (and its zone) UPPER / LOWER / PEDAL |
| ALGORITHM encoder | model 1–8 |
| PRESETS encoder | the drawbar list (vintage 1–36 = drawbar_presets_36, pipe, free reed, USER 1–16; the pedal its own list); tap SAVE to store the drawbars into a user slot |
| SEL held + white key | recall performance setup 1–16 (the 16 white keys F3 … G5); SAVE held + the key: store it |
| ARP / SEQ | vibrato (tremulant) of the manual on/off / coupler II/I |
| PLAY / REC | rotary brake / rotary slow ↔ fast (SEL + REC: the manual through the rotary or not) |
| OCT− / OCT+ | octave (−2…+3) |
| SEL (press) | shows the audio interrupt's load in % |
| SEL + HOME | panic: every note off inside, the delay and reverb tails cleared, CC 64/120/123 on all 16 MIDI channels |
| MIDI CC 1 / pitch bend | the touch strips' jobs: rotary slow/fast or bellows; bend ±2 semitones (zone screen, SEL + KNOB 4 = BEND ROTARY: rotary kick / tutti, slow/brake/fast) |
| MIDI CC 64 | sustain: holds the notes of that channel, inside and out |

**MIDI zones**: each manual has a zone with a MIDI-in channel (1/2/3), a key range (zones may overlap), an out channel,
transpose and octave, velocity through or fixed (× expression), CC and program-change filters, internal sound on/off, and
per zone a cloner, a 9-channel harmonic mapper and chord memory. The FM-1's keys follow the manual or play by the zone
ranges; an auto-pedal plays the lowest note of the lower zone; THRU passes channels no zone listens to. MIDI in and out are
both the one USB port: with a MIDI host (e.g. CME H4MIDI WC) the FM-1 sits between keyboard and synths.

The panel as it was left, 16 performance setups and the lights (sector 0) and the user drawbar slots (sector 1) are kept
in two flash sectors, written 2 s after a change once nothing sounds (a flash erase stalls the audio). The 8 setups of
version 2 become setups 1–8 (its one effect chain copied to the three manuals), the 4 registrations of version 1
setups 1–4.

The welcome screen's head is line art: `tools/gen_head_lines.py assets/gigstart2.jpg` traces the author's drawing (not in the repository) into
polylines (`firmware/gen/orgigs_head.h`, about 2 KB); the screen draws them one after the other. It is out of the
release (the screen starts with the drawbars); `./build.sh --intro-head` brings it back.

## Where this differs from the spec, and why

The spec was written against a guessed FM-1; Dinghy's platform is the tested reality:

- **No SDRAM.** The FM-1 has 96 KB RAM + a 336 KB pool. All delay memory is int16 in the pool (~160 KB):
  the 1 s stereo delay and the reverb run at half rate (their damping keeps them under 6.5 kHz); the 7.5 s
  cathedral is a 4-line FDN (the tail comes from feedback, not buffer length).
- **No second core for the app.** Sound runs in the audio interrupt (the spec's Core 1), everything else in the
  main loop (Core 0); they share only `org_par` / `org_stat` (one writer each, atomic stores).
- **44 100 Hz, 256-frame blocks** (the platform's I2S and USB audio), not 44 118 Hz / 64–128.
- **The panel**: 27 keys (F3–G5), KNOB 1–4 without push, SELECT / ALGORITHM / PRESETS encoders, 14 buttons. The
  pushes became SEL + turn and buttons (table above). **Touch strips** are not reachable from the platform:
  MIDI CC 1 and pitch bend do their jobs; the simulator draws them as sliders.
- **MIDI out is USB only.** The platform has no TRS-MIDI out and no BLE-MIDI. TRS-SAFE paces the output to
  31 250 baud with running status, for a USB-to-DIN host. Since Dinghy 0.4 the FM-1's TRS jack is a MIDI *in*
  beside USB (one queue; untested on OrGigs's device so far).
- **Wavetables** are 8 × 4 band-limited copies × 1024 samples (64 KB), not 8 × 2048: four pitch bands keep the
  bright combo waves free of aliasing up to B7 within the memory.
- **CPU**: measured in the emulator, in instructions per 256-frame block (5.8 ms): ~124 000 with nothing playing
  (the effects: rotary ~125 per sample, reverb ~170, chorus ~40, the rest ~95), ~172 000 for chords on both manuals
  and the pedal with registration 1 (version 2, one effect chain). Version 3 renders each manual on its own bus:
  in the emulator (org_prof, `-icount shift=1`) it costs 0.63 x version 2 with nothing playing (a silent bus is
  skipped) and 1.47 x with chords on all three manuals at full registration. With `-icount shift=0` the emulator's
  1 ns instructions let the LCD wait (4 000 000 polls) run out before a 240 x 64 strip has gone out at 12 MHz; use
  shift=1 there (the device's instructions are several times slower). Silent generators cost nothing (their phases are caught up when they sound
  again), the key scan runs only when a key or an envelope moves, the reverb runs at half rate. The chip's clock
  is not documented; check the load with SEL on the device.
- **Levels**: three notes come out about 10 dB under the ceiling, both manuals and the pedal at full registration
  just touch the last soft clip (gain staging in `orgigs_fx.c`, `G_IN_*` / `G_POST_*`).

Running on the FM-1 since 2026-10-23 (about 10 % DSP load at idle). Checked on the PC: pitch (A4 = 440.000 Hz on the tonewheel, reeds within ±1.2 cents), levels without clipping, no DC in silence,
the MIDI zones, the screens, and the firmware build with all of Dinghy's checks.

## The SMK-37 (Pro, Elite, MKE-P37)

The platform is Dinghy 0.4, which builds for the M-VAVE SMK-37 from the same source (`docs/SMK37.md`, the board layer
by genkigenki). OrGigs's `firmware/board/smk37/board.c` is the FM-1's panel and screens (on the SMK buttons that mean
the same: PATCH = HOME, PARA = EDIT, CHORD = ENV, NOTE REPEAT = LFO, SCALE = SEL, GLOBE = GLO, BT = SAVE) with the
SMK's own controls on top, bank PERFORMANCE: K1..K8 drawbars 1..8, fader 1 drawbar 9, fader 2 swell, fader 3 reverb
send, fader 4 volume; the pad column under a knob sets its drawbar to 0 (top) or 8 (bottom), ARP / PATCH drawbar 9,
and the pads' colours show the drawbars (six schemes, lights screen); CHORD vibrato, PARA mixer, KNOB BANK the
manual, < > the drawbar list (SCALE + < >: the model), pitch wheel bend, mod wheel rotary. All 37 keys play (C3..C6,
velocity to MIDI out). FADER BANK the next layout, KNOB BANK + FADER BANK HOME; faders 1..3 pick up, fader 3 the
MIDI out's sum. The file's head has the whole map.

**YST: a Yamaha SEQTRAK** (`firmware/core/orgigs_yst.c`, FM-1 and SMK-37). MIDI module 5, off from the factory (ENV, kept per
setup). Plugged into a SEQTRAK by USB-C (the SEQTRAK is the host), it asks what its 11 tracks hold (type, sound), one
question at a time, when switched on, when the cable comes and on REFRESH (LFO); it never waits for room to send.
It follows the SEQTRAK's sounds and knobs;
the sound names (2424) come from [jaeggerr/seqtrak-docs](https://github.com/jaeggerr/seqtrak-docs) (MIT,
`tools/gen_yst_presets.py`). The fifth MIDI screen, YST: SELECT the track (the focused zone's out channel follows),
PRESETS its sound, KNOB1..4 cutoff / resonance / attack / decay, SEL + them volume / pan / sends, ARP mute, SEQ
mono / poly / chord. The SMK-37's YST screen (GLOBE, the third MIDI screen): pads 1..11 the tracks (coloured by type; SCALE + pad: mute),
faders 1..4 cutoff / resonance / attack / decay with pickup (fader 4 is not the volume there), K1..K4 the DX's FM,
K5..K8 volume / pan / sends, < > the sound. The clone grid, the mixer and the zone screen name channels 1..11 by
track. While it is connected, what the SEQTRAK sends on channels 1..11 and its clock stay with YST (the zones
would send its own notes back to it). Tests: `tests/yst_test.py` (scripts `tests/yst.txt`, `tests/yst_elite.txt`).

```sh
./build.sh --board smk37 --model elite   # build/orgigs_fm1-smk37-elite.fwsc, identity SMK-37 Elite_970 (also pro, mke)
./build.sh                               # the FM-1 last: the SMK build overwrites build/orgigs_fm1.bin
BOARD=smk37 tests/run_host.sh tests/elite.txt      # keys, pads (their colours print at each shot), faders, wheels
sh tests/run_tests.sh                    # the update path, the loader, the packages, the flash maps, the installer
```

On the SMK the settings live in its store window (0x9D000 / 0x9E000, owner tag "ORGIGS" at 0xAF000); the head, the
pairing and key calibration (0xC0000..0xC1FFF), the stock resources and key_mac are never written. Runs on an
SMK-37 Elite (stock V016) since 2026-11-05; the FM-1 emulator does not run SMK builds.
